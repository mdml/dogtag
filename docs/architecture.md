# Architecture

> **Status: beta architecture; M0 decisions frozen 2026-07-30.** Durable obligations are separated from replaceable first-implementation choices. The beta contract is [beta.md](beta.md); the beta's milestone receipts live in the maintainers' planning record; the product repository's ADR trail is `docs/decisions/engineering/`.

- **The SDK is the product kernel.** Parsing, configuration, identity, relationships, query, validation, mutation, provenance, history, and migration live in one public semantic core. The CLI, MCP server, TUI, CI integrations, webhooks, and agent loops are consumers. An official surface may compose SDK operations but never independently reinterpret vault semantics.
- **The kernel interprets a small model; everything else is declared.** The core understands four things: a **note** (one file, frontmatter plus body), a **type** (the single discriminator every note carries, and the dispatch key for structure and validation), a **property** (a small closed lattice of value kinds, each required or optional), and a **relationship** (directed, typed, and required to resolve). Everything beyond that — lifecycle states, orthogonal flags, who may write which type — reaches the core as a *declaration* in the vault contract, and the core enforces the declared shape without knowing the vocabulary. It can answer "what is current here" because a corpus named its life axis, not because it knows the word `archived`. This is the seam that lets two corpora differ without forking the product: the smaller the set of concepts the core interprets, the fewer of one author's conventions it can mistake for facts about knowledge bases.
- **Configuration binds by capability, never by name.** A type declares zero or more capabilities, and the core reasons over those declarations. **Identity-bearing** marks the types a corpus is *about* — the targets of entity resolution and structured relationships — and admits any number, because a corpus that distinguishes people from places from organizations has three such types, not one and two impostors. **Catch-all** marks the bottom type that accepts anything so capture never blocks on classification, and admits exactly one. **Closed-write** marks types no caller may modify, which is how immutable source material becomes a policy on a class rather than a privileged location. Cardinality is part of the contract and is validated when it loads.
- **Identity is the path; the name is a shorthand.** A note's identity is where it sits in the corpus. A reference written as a bare name resolves when that name is unambiguous and reports a diagnostic *against the reference* when it is not. Repeated names are legal — daily notes filed by year, a per-directory index — because a system that refuses to open such a corpus, or demands a rename sweep before the first read, is imposing a convention rather than reading what is there. Uniqueness remains excellent authoring discipline and is never a precondition.
- **One implementation; idiomatic bindings.** The first core is Rust, exposed as a native crate and compiled into the CLI. Python, TypeScript, and later bindings wrap the same implementation and conformance suite rather than becoming parallel ports. Each language may express the API idiomatically while sharing behavior, diagnostics, and compatibility rules.
- **Dynamic orchestration, deterministic enforcement.** Agents and applications decide when and why to compose operations. The SDK decides whether identities resolve, a mutation is owned and scoped, resulting state conforms, history is attributed, and compatibility permits the operation.
- **A versioned store behind a seam.** One repository per vault is the default unit of sharing, history, and permissions; git is the first version-layer implementation, not the product definition. The SDK exposes history, attribution, scoped writes, sync state, and guest mode against the properties fixed by the [git-integration PDR](decisions/product/git-integration.md).
- **Canonical corpus semantics; local target choices.** Committed configuration gives every collaborator and SDK consumer one interpretation of the corpus. Machine-local configuration selects editor dialect, paths, integrations, and presentation. Two assets carry this in the beta and no more: one **committed vault contract** (types, properties, relationships, capabilities, the lifecycle and write-policy declarations, dialect, compatibility version) and one **local installation record** (the vault registry, actor identity, index placement). Saved views, workflows, integration bindings, and secret references are deliberately absent until the beta has evidence it needs them. Clean/smudge filters are a candidate materialization mechanism to test, not a durable architectural commitment.
- **Writes are transactions.** Public mutation starts as a plan with actor, provenance, intended file scope, diagnostics, and compatibility impact; callers validate and preview before apply. Recovery is part of the result, not a separate operational afterthought.
- **Built to ship daily.** The contract is executable: a conformance suite — round-trip property tests (parse → emit → parse is identity; dialect conversion is lossless in both directions), a golden corpus of conforming vaults, lint rules as fixtures — gates every change, and green means shippable. The suite runs **every scenario against every fixture profile**, and a scenario that can only be expressed against one profile fails the harness rather than earning an exemption; such a scenario is triaged as either an incomplete configuration model or an invariant that turns out to be one author's convention. This rule, not the prose, is what keeps personal assumptions out of the kernel. Trunk-based development; the maintainers' own vaults run HEAD as the permanent canary; semver on the SDK with `dogtag migrate` as the schema-change escape hatch.
- **State is files; everything else is rebuildable.** Canonical corpus state is the working tree; history is the configured version layer; search indexes and caches are derived artifacts that regenerate from files. Shared semantics are committed with the vault; machine configuration stays local and reproducible. No irreplaceable corpus state lives in an index, service, or surface.
- **Local by default.** Nothing leaves the machine except pushes to the remote the user chose and whatever their agent sends its model provider. No telemetry, no hosted service.
- **The vault carries its own agent contract, generated rather than written.** The instruction file an agent reads (CLAUDE.md / AGENTS.md) is **derived from the resolved contract**, so a corpus's types, required properties, predicate vocabulary, lifecycle declaration, and write policy cannot drift from the prose describing them — hand-maintained agent instructions always eventually lie, and the cost of that lie compounds as agents do more of the writing. Generation is a beta obligation. Skills as committed markdown travelling with the vault remain the intended distribution mechanism, deferred until an experiment actually exercises cold-clone onboarding; marketplaces and plugin packs are optional channels later, not the mechanism.
- **Distribution is a product surface.** The local runtime is acquired from versioned, checksummed releases; `dogtag.dev` hosts install, SDK, compatibility, migration, troubleshooting, and release documentation, and fronts the install script. No product source checkout is required to operate a vault. The beta publishes under **Apache-2.0** from a public repository, with release automation building tagged macOS and Linux artifacts on standard hosted runners; self-hosted release infrastructure remains a live fallback rather than a starting position, on the reasoning that distribution mechanics are the least interesting thing for the beta to have opinions about.
