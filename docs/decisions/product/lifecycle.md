# Note lifecycle: one state axis, the ordinary state as absence, attention, pause, and triage as flags

- **Status:** adopted — model settled 2026-06-29; amended 2026-07-23 with the triage flag, from the [inbox-workflow](inbox-workflow.md) interview. The incumbent substrate migrated to the original model, and the triage flag's substrate landed the same day it was decided (schema key, set/clear verb, indexed column, view predicate), with capture-surface birth-stamping still ahead as the per-type birth-state config table.
- **Decided / updated:** 2026-06-29; amended 2026-07-23 (triage flag); amended 2026-07-30 (declared axis)
- **Layer:** both — the substrate enforces the declared state set; surfaces filter, present, and triage by it
- **Config vs. invariant:** *Invariant* — lifecycle is a **single axis** ("where is this note in its life") whose values are a closed set, with *attention* (the notes you lean on), *work-shelving* (an effort paused, not concluded), and *triage* (structure not yet supplied) as **orthogonal flags**, never points on the life axis; and the substrate binds to the corpus's **declaration** of which property is the axis and which are the flags, never to a vocabulary it knows (amended 2026-07-30 — see Design). *Recommended but not enforced* — that the common state is the **absence** of a marker, and that "concluded but still true" and "replaced, no longer true" stay **distinct** states; both are this PDR's argued position and neither is a precondition for being read. *Config-point* — the value and flag **names**, which note-kinds may carry the pause flag, whether the ordinary state is absence or a named value, and how each surface presents and filters the states. Canonical home for a corpus's value set: each vault's committed contract, validated by the SDK's contract types (`crates/dogtag`, forthcoming — see [Architecture](../../architecture.md)).

> **Boundary.** This PDR owns the *state model* — what states a note can be in and how they're represented. The [inbox-workflow](inbox-workflow.md) PDR owns the *process* (capture → triage → file) that pays a capture's structure debt and clears the triage flag; it consumes this model, it doesn't define it. Same syntax → meaning → presentation layering the rest of the spec uses.

## 👁️ Intent

When I return to a note later, I need to know whether I can trust it as current — or whether it's still half-written, has been quietly replaced by something newer, or describes a matter that's since closed. And across the whole corpus, I need to find the handful of notes I actively work from. But lifecycle metadata is bookkeeping, and bookkeeping I have to do on *every* note is bookkeeping I'll stop doing. So the model has to make the ordinary case free and spend explicit marking only where a note genuinely deviates from "finished and current."

## 🎨 Design

**One axis, and the common case costs nothing.** Lifecycle answers a single question — *where is this note in its life?* — with a small closed set of states in which the overwhelmingly common one (finished and current) is the **absence** of any status marker. A status value appears *only* when a note departs from that default, so the mere presence of one always signals something non-ordinary.

**The states fall out of two yes/no questions.** A note is either unfinished — a **draft** — or finished. A finished note is either still the current truth or not. If it's still true, the matter it addresses is either live (the default — nothing to mark) or concluded — **archived** (set aside, but still accurate). If it's no longer true, a newer note has replaced it — **superseded** (kept for history, optionally pointing at its replacement). The fourth combination — *not true yet still live* — is incoherent, so three explicit states plus the default is the minimal set, not an arbitrary one.

**Three things people fold into lifecycle that are actually orthogonal — so they're flags, not states:**

- **Attention — "do I lean on this?"** A few notes you return to and keep editing. This is independent of where a note sits in its life: you can lean on a draft or on an archived reference. Modeling it as a status value would force the false choice "leaned-on *or* draft." It's a flag.
- **Pause — "is this effort shelved, not concluded?"** For action-bearing notes (an effort with a beginning and an end), "paused, may resume" is genuinely different from "concluded," and it too is orthogonal to the truth/life axis. A flag, carried only by the note-kinds that have work-progress.
- **Triage — "has this been given its structure?"** *(amendment, 2026-07-23.)* A note is done in two separate senses: the *content* is written — the status axis's question, draft or not — and the *structure* is supplied (typed, tagged, linked — the shape the corpus depends on). The two move independently: a capture can be finished prose with no structure; a deliberately slow draft can be fully structured. Folding "needs filing" into draft mislabels both. So it's a flag — stamped at capture, cleared by triage — and it marks the *exception*: absence means organized, the same absence-is-ordinary rule as the status axis, so the mature corpus stays unmarked. The process that stamps and clears it is [inbox-workflow](inbox-workflow.md)'s.

**The litmus for state vs. flag:** does it name a mutually-exclusive point on the one life axis (→ a state) or an independent property that can co-occur with any state (→ a flag)? "Draft" and "archived" can't both be true; "leaned-on," "paused," and "needs-triage" can sit on top of anything.

The canonical value names, the flag bindings, and which kinds carry the pause flag are config in each vault's contract.

**The substrate enforces a *declared* axis, not a vocabulary it knows.** *(Amendment, 2026-07-30.)* The model above — one axis, orthogonal flags, the ordinary case free — is the position this PDR argues for and recommends. What the substrate depends on is thinner: that a corpus **names which property is its life axis and which are its flags**, so that "show me what is current" and "show me what needs attention" are answerable without any component knowing the words a particular corpus chose. A corpus that spends a named value on its ordinary state instead of leaving it absent has made a decision this PDR argues against; it has not made itself unreadable, and the substrate must not treat it as though it had. The distinction matters because the alternative — a substrate that knows the three states by name — cannot host a corpus whose lifecycle is shaped differently without translating it, and translation at the boundary is how a system quietly makes one corpus's conventions everyone's.

The declaration is what is enforced: the axis is a closed set of values, the flags are orthogonal to it and to each other, and a value outside the declared set is a violation. Which values, and whether the ordinary state is absence, are the corpus's to choose.

## ⚖️ Tradeoffs

- **Rejected: one rich enum that encodes progress + truth + attention together.** Conflating "in progress / paused / done" with "current / replaced" with "leaned-on" into a single field breaks down three ways: the axes are independent (you can't express "leaned-on *and* draft"), "done" (work-progress) answers a different question than "replaced" (truth), and — the tell — the ordinary finished note becomes *unnameable*, because it's the note that's unremarkable on every conflated axis. One axis plus orthogonal flags makes each value carry exactly one meaning.
- **Rejected: a value for the default ("current"/"active" on every note).** A status that's present on everything carries no signal, and it taxes every record with bookkeeping for the benefit of the few that deviate. Absence is the more honest default: free to maintain, and meaningful when present.
- **Rejected: collapse to the bare minimum (one "active/archived" toggle, or capture/organize/archive).** Loses two distinctions a user genuinely acts on: *replaced-but-kept* (no longer the truth) vs. *concluded-but-true* (still the truth) — folding both into "archived" makes "is this still authoritative?" unanswerable — and *shelved-may-resume* vs. *done*. Over-collapse erases real information.
- **Rejected: per-kind lifecycle vocabularies.** Making "projects" use one state set and "reference notes" another forces the user to learn a matrix. One universal axis covers every kind; the only kind-specific element is the pause flag, which simply goes unused on notes that have no work-progress.
- **Rejected: reusing the draft state as the triage marker.** Content-completeness and structure-completeness are independent completions, so one marker can't carry both: slow drafts clog the triage lens they don't belong in, and finished-but-unfiled captures wear a "draft" label that lies about their content. The full argument is [inbox-workflow](inbox-workflow.md)'s ("structure and content are independent completions"). *(Amendment, 2026-07-23.)*
- **Tension carried, not resolved:** "is this still the truth / has it been superseded?" is a human judgment made when a note is set aside or replaced — the system can't infer it. The model makes that judgment cheap to record, not automatic.

## 🖥️ Surfaces

The state model is **substrate-enforced** and UI-independent; surfaces consume it differently.

- **CLI / SDK (authoring — where state is set).** A new note starts with no status (current) or marked draft if it's a work-in-progress; transitions go through the substrate's mutation verbs — never hand-edited frontmatter; editor completion offers the closed status set and the flags. The lint enforces the value set and that the flags stay orthogonal.
- **TUI (consumption).** The default (no status) is the normal browse view; archived/superseded drop out of active lenses by default but stay searchable; a "leaned-on" lens surfaces the pinned set; the triage lens keys on the triage flag (see [inbox-workflow](inbox-workflow.md)), with the draft state as a transitional second arm while the pre-flag draft queue drains.
- **MCP.** Status and flags are filter + return fields — an agent scopes to current (status absent), excludes superseded, or pulls the leaned-on set programmatically and remotely.
- **GUI editor (fallback).** The draft state couples to the editor's **Inbox** triage queue — drafts populate it, promotion clears it; the incumbent editor's separate `_organized` property was the triage flag's precedent, with the polarity inverted (it marked the achievement; the flag marks the exception); the attention flag reuses the editor's native **favorite/star** property rather than a parallel key; archived/superseded are ordinary frontmatter the editor displays and a saved View can filter on.
